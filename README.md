# NEON RALLY v5 — онлайн и локальная Wi-Fi сеть

## Обновить онлайн-игру
1. Замени `server.js`, `package.json` и `package-lock.json` в корне своего GitHub-репозитория. Добавь туда также `embed.html`: сервер использует его для отдельной страницы `/play`.
2. Сделай commit и дождись Live на Render. Build Command: `npm install`. Start Command: `npm start`. Root Directory: пусто, если файлы лежат в корне репозитория.
3. В `embed.html` замени `wss://YOUR-SERVER-DOMAIN.example` прежним WebSocket-адресом Render.
4. Замени весь Webflow Embed содержимым этого файла и опубликуй страницу.
5. Оба игрока обновляют страницу через Ctrl+Shift+R. Старый клиент не поддерживает новую компенсацию задержки; обнови обе стороны.

## Локальные столы: два устройства в одной Wi-Fi сети
Это отдельный сервер на компьютере, а не локальный режим с ботом. Лобби и столы на нём независимы от Render.

1. Распакуй архив на компьютер, который будет сервером. Установи Node.js 20 или новее, если он ещё не установлен.
2. В Windows запусти `start-local.bat`. При первом запуске нужен интернет для установки зависимостей. Последующие запуски используют уже установленные файлы.
   На macOS/Linux открой терминал в папке проекта и выполни `npm install`, затем `npm start`. Повторно достаточно `npm start`.
3. Оставь окно сервера открытым. Если Windows Firewall спрашивает разрешение, разреши доступ для вашей частной сети.
4. На компьютере-сервере открой `http://localhost:8080/play`.
5. В консоли сервера появятся LAN-адреса. Нужен IPv4 вашей Wi-Fi сети, например `http://192.168.1.10:8080/play`. Если адрес не появился, открой `ipconfig` в Windows и возьми IPv4 раздела адаптера Wi-Fi.
6. На втором устройстве, подключённом к той же Wi-Fi сети, открой этот LAN-адрес. `localhost` на втором устройстве не подходит — он обозначает само второе устройство.
7. Первый игрок нажимает «Создать LAN-стол», второй выбирает этот стол. Оба нажимают «Готов» за 10 секунд.

В Webflow также есть кнопка «Локальные столы · Wi-Fi»: введи `192.168.1.10:8080`, и откроется отдельная LAN-страница. HTTPS-страница Webflow не подключается напрямую к незащищённому `ws://`; локальная страница использует свой `http://` и `ws://` адрес. На странице LAN менять WS_URL не нужно: адрес подставляется автоматически. Three.js тоже отдаётся вашим локальным сервером, поэтому после установки зависимостей CDN и Render не нужны.

Если второе устройство не видит сервер, проверь IP, порт 8080, Windows Firewall и отсутствие изоляции устройств в гостевой Wi-Fi сети. Wi-Fi задержка остаётся, но интернет-маршрут и Render в этом режиме не участвуют. Один экземпляр сервера хранит столы в памяти; остановка сервера удаляет матчи.

## Исправление пропусков мяча и задержки
- Проверка удара учитывает весь путь ракетки и мяча за шаг физики, овальную форму ракетки и отображаемое смещение мяча по высоте. Ракетка автоматически встречает мяч на доступной высоте; отдельного управления высотой нет.
- Физика 120 Гц, отправка состояния до 60 Гц. Убран прежний 65-мс буфер изображения.
- Клиент рассчитывает движение между пакетами той же физикой, что и сервер, до 100 мс вперёд. Собственная ракетка отвечает сразу. Короткое предсказание удара сверяется с сервером.
- Сервер хранит недавнюю траекторию: удар, пришедший с задержкой до 140 мс, проверяется по истории. После пропущенного корректного мяча есть окно 100 мс для уже отправленного возврата. Идентификаторы розыгрыша и удара защищают от запоздалых повторных команд.
- Пинг показан в интерфейсе. TCP_NODELAY включён; при переполнении исходящего буфера старые состояния не добавляются в очередь.

Это уменьшает влияние задержки, но не убирает расстояние до сервера, плохой Wi-Fi, потери пакетов или задержки хостинга. При большом пинге возможны корректировки положения мяча. LAN обычно лучше для игры в одной сети. Сравнительный замер на вашем Render не выполнен.

## Управление и правила
Своя сторона снизу. Ракетка следует за мышью по всей своей половине, включая пространство за столом; курсор над полем скрыт во время розыгрыша. Подача: новый клик, затем коснись неподвижного мяча ракеткой. Боковой взмах придаёт боковое вращение; метка и процент показывают вращение. Топспин и нижнее вращение отдельно не управляются.

Стол 72 × 144, ракетка радиуса 8, боковые стены высотой 32, поле движения 128 × 240. Допустим один рикошет от стены на половине соперника после каждого удара. Рикошет на своей половине или второй до нового удара — фол. Выше стены мяч летит свободно; торцевых стен нет. Мяч должен пересечь сетку и один раз отскочить на половине соперника. Удар до отскока — фол. Второй отскок или пропущенный корректный мяч — очко ударившему. Попадание в сетку, свою половину или за стол до корректного отскока — очко сопернику.

Подача упрощённая: сразу на половину соперника, без первого отскока на своей. Подаёт победитель розыгрыша. Игра до 9, преимущество 2. Между розыгрышами 1,8 секунды. Отключение — пауза до 15 секунд. Посетители лобби видят занятые столы и счёт; режима наблюдения за самой ареной нет.

## Проверки
```
node --check server.js
node physics-test.cjs
node client-test.cjs
node network-test.cjs
```
Проверены траектории, отскоки, вращение, обе проекции столкновений, быстрые взмахи, задержанные и повторные удары, истечение окна компенсации, счёт и паузы. Сетевой тест запускает отдельный сервер, три WebSocket-клиента, готовность двух игроков, шесть возвращённых ударов, пинг, счёт в лобби и выдачу локальных файлов Three.js. Клиентский тест проверяет логику со вспомогательной имитацией DOM/WebGL; визуальная проверка в настоящем браузере не выполнена.

При изменении серверной физики выполни `node build-embed.cjs`, чтобы обновить идентичные функции предсказания в `embed.html`, затем обнови весь Embed.
